## 1. コンセプト

**X（旧 Twitter、https://x.com/ ）を開いているときに、ページ上の動画／画像を「プレイリスト」として自動または任意に連続再生する Google Chrome 拡張機能。**

- 「タイムラインを眺めながら動画を 1 本ずつ開く」手間をなくし、メディア再生ソフトのように X のメディアを流し見できるようにする。
- ダウンロード機能は持たない。あくまで **プレイリスト作成と自動再生** に特化する。
- UI の参考：Video DownloadHelper（https://downloadhelper.net/ ）のプレイリスト UI。該当する機能のみ取り入れる。
- **UI は「AI が作ったような見た目」にならないよう仕上げる。** そのために有用な Skill があれば使用・導入してよい（ホスト承認済み）。

## 2. 対象ユーザー・利用シーン・前提

- X を Chrome で閲覧しているユーザー（ログイン済み）。
- タイムライン／ブックマーク／いいね など、メディアが並ぶページを開き、拡張機能を起動して流し見する。
- **個人利用が前提。** 公開配布（ストア公開など）は想定しない。
  X の内部仕様変更で動かなくなった場合は**作り直しも許容する**（ホスト承認済み）。

## 3. スコープ

### やること

- 自動プレイリスト（現在開いているページのメディアを自動収集）
- 任意（マニュアル）プレイリスト（ポストの右クリックメニューから追加）
- 画面右側のサイドパネル（プレイリスト表示・編集、再生操作、設定）
- 再生ウィンドウ（メディア再生ソフト相当の操作＋メディア情報表示）
- 拡張機能設定
- 前後メディアの先読み（切り替えの待ち時間を減らす）
- §4.6 の追加機能（ホスト承認済みの提案。**技術的に可能な範囲で**すべて実装する）

### やらないこと

- **メディアのダウンロード機能は一切実装しない。**
- **プレイリストの永続保存（URL 紐づけ等）は作らない。** ただし再生順序の変更と「プレイリスト中のどこまで再生したか」の一時的な保持はあり（§4.5）。
- **メディア内の再生秒数（何秒目まで見たか）は保存しない。**
- **複数タブでの同時動作**は対象外。拡張機能を起動したタブ 1 つで動作する。

## 4. 機能要件

優先度：**必須**＝初期版の中核、**推奨**＝初期版に含めるが中核が成立してから、**低**＝後回し可。

### 4.1 メディアの収集

| # | 要件 | 優先度 |
|---|---|---|
| F-01 | 自動プレイリストを ON にすると、現在開いているページ（タイムライン、ブックマーク、いいね など）にあるメディアを自動的にプレイリストへ登録する。**登録しても再生は自動では始めない**（再生開始は F-16 に従う） | 必須 |
| F-02 | 再生が読み込み済みの末尾に近づいたら**自動でページをスクロール**し、さらに下のメディアを読み込んでプレイリストに追加する。X の読み込み制限を避けるため、少しずつ・間隔を空けて行う。**自動スクロールは再生中のみ**行い、再生していないときはページを動かさない | 必須 |
| F-03 | 任意プレイリストは、**ポストを右クリック →「プレイリストに追加」**で、そのポストに含まれるメディアをすべて追加する（動画の上ではなくポスト上で右クリックする。Chrome 標準の右クリックメニューに項目を出す） | 必須 |
| F-04 | 1 ポストに複数（最大 4 つ）のメディアがある場合は**すべて**対象にし、**メディア 1 つにつきプレイリスト 1 項目**として登録する | 必須 |
| F-05 | 画像もメディアとして扱う。プレイリストに含めるかは設定で切り替える（→ S-03） | 必須 |
| F-06 | GIF（X では実体は動画）は**動画として扱い、表示時間は画像と同じ設定（S-04）に従う** | 推奨 |
| F-07 | **重複メディアの除外**。リポストや引用で同じメディアが複数回並ぶ場合は 1 回だけ登録する（S-16 で切替） | 推奨 |
| F-08 | 右クリックメニューに「**次に再生**」も用意する（末尾追加とは別） | 推奨 |
| F-09 | X 内でページを移動したら（タイムライン → ブックマーク など）、**自動プレイリストは新しいページの内容で作り直す。マニュアルプレイリストはそのセッション中は保持する** | 必須 |

| # | 要件 | 優先度 |

| F-51 | 再生順序を変更した場合、その順序を**一時的に**（そのセッションの間）保持する | 低 |

## 6. 非機能要件

| # | 要件 |
|---|---|
| N-01 | メディア切り替え間の待ち時間を極力少なくする |
| N-02 | 先読みによる負荷（メモリ・通信量）は許容範囲に収める。既定は「次の 1 件・最低画質・冒頭数秒」 |

## 7. 技術的な前提・制約（ホスト了承済み）

| # | 内容 | 方針 |
|---|---|---|
| T-01 | 動画の実体 URL は、X がページ表示のために内部で受け取っている投稿データを拡張機能側で読み取って得る。X の内部仕様変更で突然壊れる可能性がある | **この方式で実装する**（ホスト了承）。壊れたら作り直しも許容 |
| T-02 | 長時間動画は直接再生できる形式が用意されていない場合がある | 収集時に「直接再生できる形式があるか」を判定し、無いものは初期版では**再生不可として表示しスキップ**する。ストリーミング再生の対応は後回し（§9.2 参照） |
| T-03 | 自動スクロールによる X の読み込み制限 | 少しずつ・間隔を空けて行い、制限を検知したら待って再開する |
| T-04 | X は画面外の投稿を画面から消すため、画面上の要素に頼れない | T-01 のデータを基にプレイリストを持つ |
| T-05 | 動画上の右クリックは X の独自部品に阻まれる | **ポスト上で右クリック**し、そのポストのメディアをすべて追加する（F-03） |
| T-06 | サイドパネルと再生ウィンドウの描画方式 | **X のページ内に描画**する。再生ウィンドウは浮かぶ小窓を第一候補、難しければ再生開始時にページ領域いっぱいに表示（F-4B）。フルスクリーンは「再生ウィンドウとサイドパネルを含めた領域」を全画面にする形で実現し、パネルを表示したままにする（F-1C） |
| T-07 | 先読みの負荷 | 既定「次の 1 件・最低画質・冒頭数秒」。S-12 で調整 |
| T-08 | X 内でのページ移動 | 自動プレイリストは作り直し、マニュアルは保持（F-09）。ブックマークといいねは 2026-09 時点で `x.com/i/history`（タブ切替）に統合されている |
| T-09 | 並べ替えとスクロール追加の両立 | 自動時は並べ替え OFF を初期方針とする |
| T-10 | 複数タブ | 起動したタブ 1 つで動作 |
| T-11 | X の利用規約 | 個人利用の範囲に留める |

## 8. ホストが明示した妥協点

- 自動プレイリストで並べ替えの実現が難しい場合は、**自動時のみ並べ替えを OFF** にしてよい。
- 再生順序の変更は**優先度が高くない**。
- プレイリストの保存機能は**今回は作らない**。
- X の仕様変更で壊れた場合は**作り直しも許容**する。

### 9.2 長時間動画の「目安」について（ホストの質問への回答）

- 境目は**動画の長さそのものではなく、X がその動画に「直接再生できる形式」を用意しているかどうか**で決まる。長さはあくまで傾向。
- 傾向として、**無料アカウントの上限（2 分 20 秒）以内の動画にはほぼ確実に直接再生できる形式がある**。
  Web 版で自動ループしなくなる 1 分の境目は**表示上の挙動であり、形式には関係ない**。
- 直接再生できない可能性があるのは、**有料プランで投稿された長尺動画**（数十分〜数時間）や、ライブ配信の録画など。
- したがって初期版では「2 分 20 秒」を固定の閾値にはせず、**収集時に 1 本ずつ形式を確認**し、無いものだけ再生不可としてスキップする（T-02）。
  ホストのタイムラインに長尺動画が多いなら、ストリーミング対応の優先度を上げる。
